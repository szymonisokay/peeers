## Purpose / Big Picture

Peeers is a shopping-list and notes app for people who share a flat. Its UI is
fully specified by 41 mockups in `assets/design/`, and those mockups reuse the
same handful of visual elements over and over: a card, a row with a title and a
subtitle, a circular checkbox, a pill-shaped chip, a coloured avatar with an
initial, an uppercase section label.

Right now none of those exist. Every screen built from here on would re-derive
its own padding, its own row height and its own text colours, and they would
drift apart — especially in the dark theme, which has its own token values.

After this change a developer can open one screen in the app, see every
primitive rendered side by side in both light and dark themes, and build any
later screen by composing them instead of inventing them. Nothing user-facing
ships; this is the vocabulary that makes M2 onward cheap and consistent.

## Surprises & Discoveries

- Observation: the app crashed with "Element type is invalid ... but got: number"
  the first time `/gallery` was opened.
  Evidence: `ICONS[name]` returned a number, meaning Metro still treated `.svg`
  as a static asset. The dev server had been started before `metro.config.js`
  existed. Restarting with `npm start -- --clear` fixed it. The plan already
  warned about this; the step was simply missed.

- Observation: `assets/illustrations/pusta-lista.svg` rendered as blank space.
  Evidence: its `stroke` attributes used `oklch(...)` colour values, which
  `react-native-svg` cannot parse. Converted the four values to their sRGB hex
  equivalents in place: `oklch(0.9 0.015 275)`→`#DBDDE8`,
  `oklch(0.88 0.02 275)`→`#D3D7E5`, `oklch(0.93 0.012 275)`→`#E5E7F0`,
  `oklch(0.52 0.17 275)`→`#505AC8` (the brand accent, confirming the
  illustration was authored against the same spec).

- Observation: the illustration did not adapt to the dark theme — its card was
  `fill="#fff"`, staying bright white against `#14161B`.
  Resolution: a dark file was derived rather than hand-picked. Each stroke's
  oklch lightness was mirrored around the surface: a stroke 0.10 below white
  (`#DBDDE8`) became 0.10 above `#1B1E25` (`#34363F`); likewise `#D3D7E5`→
  `#393B47` and `#E5E7F0`→`#2D2F35`. Card fill and accent map straight onto the
  `surface` and dark `accent` tokens. Verified on the simulator in both themes.

## Decision Log

- Decision: The gallery lives at its own route `src/app/gallery.tsx`, not in
  `src/app/index.tsx`.
  Rationale: M2 replaces `index.tsx` with the Przestrzeń feed. Putting the
  gallery on its own route means M2 does not have to move or delete it, and it
  stays available as a visual reference for the rest of the project.
  Date/Author: 2026-08-19, planning.

- Decision: There is no `Sheet` primitive. Bottom sheets are **routes** with
  `presentation: 'formSheet'`, which makes presentation the navigator's job and
  moves it out of this milestone into M2.
  Rationale: verified against the installed expo-router 57.0.14, which vendors a
  native-stack supporting `presentation: 'formSheet'` on iOS and Android, plus
  `sheetAllowedDetents` (accepting the literal `'fitToContents'`, which is what
  every sheet in the mockups needs), `sheetGrabberVisible`, `sheetCornerRadius`
  and `sheetLargestUndimmedDetentIndex`. This yields native drag-to-dismiss,
  scrim and safe-area handling for free, and gives each sheet its own URL. A
  hand-built sheet would reimplement all of it worse.
  Consequence: what is left of a sheet is its *content*, which is already
  covered by `SectionLabel`, `ListRow`, `Button` and `Card` from Milestones 2
  and 3. Nothing extra is needed here.
  Date/Author: 2026-08-19, planning.

- Decision: `sheetGrabberVisible` is iOS-only; Android will not draw the grab
  handle visible in the mockups.
  Rationale: the type is annotated `@platform ios`. The mockups are iPhone
  renders, and matching native platform behaviour beats forcing an iOS
  affordance onto Android. Do not hand-draw a grabber to compensate.
  Date/Author: 2026-08-19, planning.

- Decision: `react-native-svg-transformer/expo` resolves and works in Expo Go;
  the fallback was not needed.
  Rationale: verified by `require.resolve` and by the bundle containing the
  transformed components. The assumption in this plan is confirmed.
  Date/Author: 2026-08-19, implementation.

- Decision: component sizes derive from the spacing scale rather than fixed
  pixel heights.
  Rationale: AGENTS.md forbids inventing design values, and no button or row
  height exists in the tokens. Deriving from `spacing` also means components
  grow with the text-size setting from `22` once that is wired up.
  Date/Author: 2026-08-19, implementation.

- Decision (superseded): fallback if `react-native-svg-transformer` cannot be
  made to work in Expo Go. The fallback is to hand-write each icon as a
  `react-native-svg` component in TypeScript (`<Svg><Path d="..."/></Svg>`),
  keeping `assets/icons/*.svg` as the source of truth for the path data. This
  costs a manual transcription step per icon but removes the bundler dependency
  entirely. To be recorded in Milestone 1.

## Context and Orientation

This repository is an Expo SDK 57 app using expo-router, written in TypeScript.
It runs in Expo Go — there is no development build. Read AGENTS.md at the root
before starting; it is short and its constraints are binding.

Terms used below:

- **Przestrzeń** — the shared container for lists, notes and people. Polish
  domain term; it stays Polish in code and prose. See `docs/PROJECT.md`.
- **Token** — a named design value (a colour, a spacing step, a text style)
  defined in `src/theme/tokens.ts` and read through the `useTheme()` hook.
- **Primitive** — a small, reusable presentational component with no knowledge
  of the app's data.

Current state of the code — this is all of it:

    src/app/_layout.tsx     Stack + Public Sans font loading + StatusBar
    src/app/index.tsx       throwaway token preview, to be replaced
    src/theme/tokens.ts     colours (light + dark), typography, spacing, radius
    src/theme/index.ts      useTheme() hook, re-exports everything from tokens

`useTheme()` returns `{ scheme, colors, typography, spacing, radius, fontFamily }`.
`colors` is already resolved for the active scheme, so components never branch on
light vs dark themselves.

Routes affected: `src/app/index.tsx` (replaced with a link), `src/app/gallery.tsx`
(new).

Mockups that specify the primitives, by number in `assets/design/`:

- `03` — avatar stack in the header, summary cards, feed rows, tab bar
- `07` — checkbox rows, struck-through checked items, section labels
- `11` — segmented control ("Każdy / Admin"), toggle, list rows
- `15` — empty state with illustration, chips
- `32` — primary and secondary buttons
- `35` — progress bar, cards, pinned section
- `38`, `39`, `40` — the dark-theme counterparts of `03`, `07`, `10`

No new token is required. No mockup listed under
`docs/DESIGN.md` -> "Known mockup defects" is relied on here.

This milestone touches nothing listed under `docs/PROJECT.md` ->
"Deliberately out of scope".

### Milestone 1: SVG pipeline and the complete icon set

At completion, any `.svg` in `assets/icons/` can be imported as a React
component, six previously missing icons exist, and `/gallery` renders all 22 in
both themes.

Scope:

1. Install the transformer:

        npx expo install react-native-svg-transformer

2. Create `metro.config.js` at the repo root:

        const { getDefaultConfig } = require('expo/metro-config');

        const config = getDefaultConfig(__dirname);

        config.transformer.babelTransformerPath = require.resolve(
          'react-native-svg-transformer/expo'
        );
        config.resolver.assetExts = config.resolver.assetExts.filter(
          (ext) => ext !== 'svg'
        );
        config.resolver.sourceExts = [...config.resolver.sourceExts, 'svg'];

        module.exports = config;

   If `react-native-svg-transformer/expo` does not resolve, try
   `react-native-svg-transformer` (the non-Expo entry). If neither works in
   Expo Go, take the fallback recorded in the Decision Log and note the finding
   under Surprises & Discoveries.

3. Create `src/types/svg.d.ts` so TypeScript accepts the imports:

        declare module '*.svg' {
          import type { FC } from 'react';
          import type { SvgProps } from 'react-native-svg';
          const content: FC<SvgProps>;
          export default content;
        }

4. Add the six missing icons to `assets/icons/`. Match the existing convention
   exactly — open `assets/icons/szukaj.svg` first and copy its root element.
   Every file uses:

        <svg xmlns="http://www.w3.org/2000/svg" width="24" height="24"
             viewBox="0 0 24 24" fill="none" stroke="currentColor"
             stroke-width="1.9" stroke-linecap="round" stroke-linejoin="round">

   Contents, one file each:

   - `chevron-prawo.svg` — `<path d="M9.5 5.5 16 12l-6.5 6.5"/>`
   - `chevron-lewo.svg` — `<path d="M14.5 5.5 8 12l6.5 6.5"/>`
   - `strzalka-dol.svg` — `<path d="M5.5 9.5 12 16l6.5-6.5"/>`
   - `plus.svg` — `<path d="M12 5v14"/>` and `<path d="M5 12h14"/>`
   - `strzalka-w-gore.svg` — `<path d="M12 19V5"/>` and `<path d="M6 11l6-6 6 6"/>`
   - `wiecej.svg` — three dots, filled rather than stroked:

            <circle cx="5" cy="12" r="1.6" fill="currentColor" stroke="none"/>
            <circle cx="12" cy="12" r="1.6" fill="currentColor" stroke="none"/>
            <circle cx="19" cy="12" r="1.6" fill="currentColor" stroke="none"/>

     Filled shapes inside an otherwise stroked set are already used by
     `assets/logo/peeers-mark.svg`, so this is consistent.

5. Create `src/components/Icon.tsx`. It maps a name to the imported component
   and forwards size and colour. Because every SVG uses `currentColor`, passing
   `color` is enough to recolour it:

        export type IconName = 'szukaj' | 'notatka' | ... ;  // all 22

        export function Icon({ name, size = 24, color }: {
          name: IconName; size?: number; color: string;
        }) { ... }

   Build the name-to-component map with static imports; do not construct import
   paths at runtime, because Metro cannot bundle those.

6. Create `src/app/gallery.tsx` rendering every icon in a grid with its name
   underneath, on the themed background.

7. Replace the body of `src/app/index.tsx` with a minimal screen containing a
   link to `/gallery`. Keep it short — M2 replaces this file entirely.

Acceptance:

    npx tsc --noEmit
    # Expected: no output, exit code 0

Then open `/gallery` in the running app and confirm all 22 icons render, are

### Milestone 2: Foundational primitives

At completion, seven primitives exist under `src/components/ui/` and appear in
the gallery.

Build, in this order:

- **`Text`** — wraps React Native's `Text`. Prop `variant` selects from
  `typography` (`titleLarge`, `title`, `body`, `bodyMedium`, `bodySmall`,
  `label`), prop `tone` selects `text` (default) or `muted`. This is what stops
  later screens from reaching into tokens directly.
- **`Screen`** — safe-area container with the themed background and standard
  horizontal padding (`spacing.lg`). Optional `scroll` prop.
- **`Card`** — surface background, `radius.md`, hairline border in
  `colors.border`, `spacing.md` padding. Seen on `03` and `35`.
- **`SectionLabel`** — the uppercase grey heading above groups
  ("DZIŚ W PRZESTRZENI", "DO KUPIENIA"). Uses the `label` typography variant.
- **`Button`** — three variants: `primary` (accent fill, white label, pill
  radius), `secondary` (transparent fill, accent label, hairline border),
  `plain` (accent label only). Full-width by default; see `32`.
- **`Chip`** — pill with `selected` state. Selected is accent fill with a white
  label; unselected is a neutral fill with the default text colour. Seen on
  `01` (Dom / Praca / Wyjazd) and `15`.
- **`Avatar`** — coloured circle with the first letter of a name. Props: `name`,
  `color` (one of `avatarColors` from tokens), `size`. Add an `AvatarStack` that
  overlaps several with a small negative margin, as in the `03` header.

Append each to the gallery as it is built.

Acceptance:

    # Expected: no output, exit code 0

Then compare the gallery against `32` (buttons), `01` (chips) and `03`

### Milestone 3: Composite primitives

At completion, the gallery shows every element the later screens need.

- **`ListRow`** — title, optional subtitle, optional right-hand slot, hairline
  bottom separator, minimum height matching `07`. The workhorse of the app.
- **`CheckboxRow`** — `ListRow` plus a circular checkbox on the left. Unchecked
  is an empty ring; checked is an accent-filled circle with a white tick using
  the `odhaczone-grube` icon, and the title is struck through and muted. See
  `07` and its dark counterpart `39`.
- **`ProgressBar`** — thin rounded track with an accent fill, driven by a `0..1`
  value. Seen on `35`.
- **`SegmentedControl`** — two or more options, the selected one filled with the
  accent. Seen on `11` ("Zapraszać może: Każdy / Admin").
- **`Toggle`** — wraps React Native's `Switch`, coloured from the tokens.
- **`EmptyState`** — illustration, title, body text, optional chips underneath.
  Takes the illustration as a prop. Exercise it with
  `assets/illustrations/pusta-lista.svg`, matching `15`.

There is deliberately **no `Sheet` component**. The bottom sheets on `04`,
`05`, `06`, `12`, `14`, `19`, `24`, `28` and `37` are routes presented with
`presentation: 'formSheet'`, configured in M2. Their contents are built from the
