# Peeers

Shared shopping lists and notes for people who live together.

A mobile app (iOS/Android) built with Expo SDK 57 and expo-router. No accounts
and no passwords — a person is a name and a color stored on the device.

## Getting started

```bash
npm install
```

Android builds need **JDK 17**. Android Studio bundles JDK 25, and from JDK 24
a restricted call in `java.lang.System` breaks the Android Gradle Plugin's CMake
configuration — `react-native-screens` and `react-native-worklets` both fail.

```bash
brew install openjdk@17
```

The JDK is pinned for every Gradle build in `~/.gradle/gradle.properties` via
`org.gradle.java.home`. It cannot live in `android/gradle.properties`: that
directory is generated by `expo prebuild` and is discarded on the next run.

That pin covers the JDK Gradle *builds* with, and it cannot cover the one Gradle
*starts* on — the wrapper has to be running before it can read a Gradle
property. So the shell needs `JAVA_HOME` as well, and it needs `ANDROID_HOME`,
because nothing else tells Gradle where the SDK is. Homebrew installs openjdk
keg-only, so `/usr/bin/java` stays the macOS stub that answers "Unable to locate
a Java Runtime". Both belong in `~/.zprofile`:

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
```

The error message for the second one suggests writing `sdk.dir` into
`android/local.properties` instead. Do not — that file lives in the generated
directory, for the same reason the JDK pin does not.

### Running

Both platforms run from a development build, started with:

```bash
npm run dev
```

Then press `i` or `a`.

Expo Go is no longer enough. `formSheet` collapses to zero height there on
Android 13, because Expo Go's window is not edge-to-edge and
`react-native-screens` sizes sheets against a window that is. A development
build sets `edgeToEdgeEnabled=true` and the sheet renders in full.

Rebuild a platform only when native code or config changes:

```bash
npm run android
```

```bash
npm run ios
```

`android/` and `ios/` are generated by `expo prebuild` and are git-ignored — do
not edit them by hand, and expect anything written there to be discarded.

## Verification

```bash
npx tsc --noEmit
```

After editing `src/db/schema.ts`, regenerate the migration. The app applies
pending migrations on startup, so a schema change without this has no effect on
the device:

```bash
npm run db:generate
```

There are no tests and no configured linter yet. `npm run lint` will launch an
interactive ESLint wizard on first use.

## Layout

| Path | Contents |
|---|---|
| `src/app/` | expo-router routes (file-based routing) |
| `src/theme/` | design tokens — values only |
| `src/hooks/` | hooks, including `useTheme` |
| `src/components/` | icons, illustrations and the UI primitives |
| `src/db/` | SQLite schema, event log, actions and queries |
| `src/i18n/` | language detection and the i18next setup |
| `src/lib/` | helpers — grammar, dates, parsing |
| `messages/` | every user-visible string, as `pl.json` and `en.json` |
| `assets/design/` | 41 PNG mockups — the UI spec |
| `assets/icons/`, `assets/logo/`, `assets/illustrations/` | source SVGs |
| `docs/` | project knowledge |

The app speaks Polish and English, chosen from the phone's own language at
startup with English as the fallback. Every user-visible string lives in
`messages/pl.json` and `messages/en.json` — never in a component — and a new
string is a new key in both files. Everything else in this repo, documentation
and code comments included, is written in English. See [AGENTS.md](AGENTS.md).
